      How it works

      Anthropic evaluates prompt caching against a cumulative prefix in a fixed order: tools, then the system prompt, then messages, in conversation order. A cache_control marker on any block is a breakpoint: everything from the start of the request up to and including that block is what gets cached. This tool rebuilds that same ordered list from your pasted JSON, marks which blocks fall at or before each breakpoint, and scans only the blocks that are actually cached for content that looks like it changes on every request.

      What it checks

      • ISO 8601 timestamps and calendar dates, for example 2026-07-06T14:32:07Z.
      • UUIDs, the standard 8-4-4-4-12 hex format used for request and session ids.
      • Unix epoch timestamps in seconds or milliseconds, the shape a raw Date.now() call produces.
      • Per-request identifiers: a small heuristic for tokens like session_, request_, or trace_ followed by an id.
      • Relative-time phrases such as "current time" or "as of now", a sign the surrounding text is likely generated fresh per call.

      This is a heuristic, not a guarantee. It only flags content it recognizes, and it can miss a dynamic value with no obvious shape (a user's name, for example). It also only scans text it can read: image blocks are skipped since they carry binary data, not authored text. Content placed after the last breakpoint is never flagged, because uncached content is expected to change on every call; that is exactly where dynamic content belongs.
